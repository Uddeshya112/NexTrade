# NexTrade patch set — 2026-10-09

This patch modifies the current repository source, not the revision-specific snippets in the pasted repair plan.

## Changes made

- Public registration always creates a `TRADER`; a caller-supplied role cannot grant `ADMIN`, `RISK_MANAGER`, or `SUPPORT`.
- Removed the fixed JWT signing secret from `ServiceConfiguration`. Startup now requires a `JWT_SECRET` with at least 32 UTF-8 bytes and supports an optional previous key through `JWT_PREVIOUS_SECRET` plus `JWT_KEY_ID_PREVIOUS`.
- REST bearer authentication checks the backing session and subject on every request, so logout, refresh rotation, and password-reset revocation invalidate access tokens immediately.
- Wallet creation/reconstitution and cash mutations reject negative balances and non-positive transaction amounts.
- Order creation and persisted-order reconstitution reject zero/negative and tick-misaligned limit/stop prices using the instrument's tick size, rather than trusting the client-supplied `Price.tickSize`.
- FOK preflight ignores same-owner resting orders that self-trade prevention would remove during matching, avoiding partial FOK executions caused by an inaccurate liquidity estimate.
- Fixed sell-side self-trade prevention to cancel/remove the resting buy order rather than cancelling the incoming sell and orphaning the buy order.
- Made the stop-trigger guard a recursion-depth guard rather than a cumulative per-command counter, so a long batch of independent trades does not suppress later stop triggers after 64 calls.
- Replaced the existing uncompilable placeholder/property-test draft with deterministic matching invariants, and added wallet negative-amount regression tests.
